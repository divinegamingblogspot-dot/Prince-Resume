A portfolio built as a connected system

Portfolio architecture · front-end engineering · discoverability

Project breakdown

01

The challenge

A portfolio can become a long, unfocused page where recruiters, collaborators and potential clients struggle to find the information relevant to them. Prince.OS is organised into focused routes for work, career, profile, systems, insights, blog, studio and contact.

02

Information architecture

Related legacy pages are connected through combined destinations such as Work, Career and Profile while their original routes remain available. Internal links, topic pages and project case studies provide multiple ways to reach the same relevant evidence without forcing every visitor through one long scroll.

03

Interface and accessibility

The system includes responsive layouts, multiple themes, mobile navigation, keyboard shortcuts, a command palette, reduced-motion support and a focus mode. Motion is an enhancement; core content and navigation should remain available without relying on animation.

04

Nova and contextual help

Nova is a portfolio-native assistant interface designed to explain the site's projects, skills and background. The interface uses local contextual knowledge and does not depend on a live OpenAI API integration in the current build.

05

Search and maintainability

Pages use descriptive titles, metadata, canonical URLs, structured data, robots rules and a sitemap. GitHub Actions runs JavaScript syntax checks and a custom validator for local links and metadata before deployment.

06

Verification boundary

A successful static-site workflow confirms the checks included in CI, not every real-device interaction or a Lighthouse score. Search indexing, rankings, Core Web Vitals and conversion outcomes require separate measurement.
